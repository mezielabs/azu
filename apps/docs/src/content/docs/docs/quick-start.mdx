Generate a resource for the starter kit's `User` model. In an existing app, you can use another model with a migrated table.

Before you start, complete [Installation](/docs/installation/) and allow your account through `accessAdmin`. Run commands from your app's root directory. This walkthrough uses the React starter kit's `User` model and signup routes.

For a business model with relationships and its own rules, follow [Add an existing model](/docs/guides/existing-model/).

<Steps>

1. Run your migrations:

   ```sh
   node ace migration:run
   ```

2. Generate the resource. The generator reads the model and its database table.

   ```sh
   node ace azu:resource User --policy
   ```

   Check that `app/admin/resources/user_resource.ts` exists. The generated files are listed below.

3. Start your dev server.

   ```sh
   npm run dev
   ```

4. If you already have the allowed account, sign in at `/login`. Otherwise, sign up at `/signup` with the email you allowed in [`accessAdmin`](/docs/installation/#let-people-in).

5. Open `/admin` and choose **Users**. Open your user, choose **Edit**, change a non-sensitive detail, and save. Reload the record to check that the change persisted.

   Use the app's signup page to create users. The generated policy omits `create` because the required password has no generated admin field.

</Steps>

## What the generator writes

For `User`, `azu:resource` writes these files:

- The resource in `app/admin/resources/user_resource.ts`.
- Create and update validators in `app/validators/user_admin.ts`. The starter kit already has `app/validators/user.ts`. Pass `--no-validator` to skip generating validators.
- With `--policy`, a policy in `app/policies/user_policy.ts` if that file is missing.

Anyone who passes `accessAdmin` can list, view, and edit users under the generated policy. It denies deletion by omitting `delete`. Review the resource and restrict the policy to the roles you want before deploying.

## Typecheck

Run `node ace codegen` once before you typecheck:

```sh
node ace codegen
npm run typecheck
```

Bouncer's middleware imports `#generated/policies`, which codegen writes. So `npm run typecheck` fails on a fresh app until codegen has run once. The dev server runs it for you.

Then check the resource configuration:

```sh
node ace azu:doctor
```

Resolve errors for Users and review warnings. Doctor checks configuration, but doesn't prove your access rules are correct.
