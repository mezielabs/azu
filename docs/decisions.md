# Decisions

Newest at the bottom. Each entry: date, decision, why.

- **2026-10-09 · Name: Azu, published as `@mezielabs/azu`.** Igbo for "back". The unscoped `azu` name and `@azu` scope are taken on npm, and the company scope builds Mezie Labs' authority. Front-end package: `@mezielabs/azu-react`.
- **2026-10-09 · React first.** Inertia + React 19 for v1. Vue waits for demand, so keep the component contract framework-neutral where it's cheap.
- **2026-10-09 · Inertia, not Edge.** Matches how most AdonisJS 7 apps are built and differentiates from adonis-admin (Edge-based).
- **2026-10-09 · Reuse app code for rules.** Permissions come from Bouncer policies and validation from VineJS validators named on each resource. Azu adds no rule system of its own.
- **2026-10-09 · Open core.** MIT core; Pro extensions as separate private packages that plug into core extension points. Pro licence checks happen at install and update, never at runtime.
- **2026-10-09 · Scope: AdonisJS 7 and Lucid only.** Postgres, MySQL, and SQLite supported.
- **2026-10-11 · Monorepo with pnpm workspaces.** `packages/core`, `packages/react`, `apps/demo`. Revisit in the spike if AdonisJS package tooling fights it.
- **2026-10-11 · Monorepo tooling confirmed in the spike.** pnpm workspaces work with the AdonisJS package tooling (tsdown, ts-exec, Japa). Core builds with tsdown per the AdonisJS package starter kit; `@mezielabs/azu-react` builds with `tsc` plus the Tailwind CLI and ships `src/` for `admin:publish`. The demo consumes built output, so root scripts build packages first.
- **2026-10-11 · Demo runs on SQLite during the spike.** It's the starter kit default and needs no server. Postgres (primary) and MySQL come with the Phase 1 integration suite.
- **2026-10-11 · Root `pnpm dev` uses `node ace serve --watch`, not `--hmr`.** `--hmr` crashes in a ts-exec loader hook on Node 24.3.0 even in the unmodified starter. Revisit once local Node is upgraded.
- **2026-10-12 · `pnpm dev` back on `--hmr`; local Node is 24.21.0.** The `--hmr` crash was Node 24.3.0, not Azu or the starter: on 24.21.0 the dev server boots, serves `/admin`, and survives a backend hot reload. `.nvmrc` pins Node 24. Supersedes the `--watch` entry above.
- **2026-10-12 · React Aria Components for `@mezielabs/azu-react`, including its table.** The table covers sorting, row selection, keyboard navigation, and column resizing. Why: async combobox for `belongsTo`, timezone-aware date pickers, WCAG AA, and built-in i18n out of the box. A Vue front end comes later as a separate `@mezielabs/azu-vue`, likely on Reka UI.
- **2026-10-12 · Tiptap 3 for `richText`, as an optional peer dependency loaded lazily.** It loads only when a resource uses `field.richText()`, so apps without rich text pay nothing. Apps can swap the editor through the component override.
- **2026-10-12 · No TanStack Table in v1.** The server owns sorting, filtering, and pagination, and React Aria's table covers the rest. Revisit if users ask for column pinning or reordering; TanStack's official `kitchen-sink-react-aria` example is the template.
- **2026-10-12 · No TanStack Query yet.** Async combobox search uses `fetch` with `AbortController`. Revisit when a second use case appears, such as global search or Pro widgets.
- **2026-10-12 · React Aria and Tiptap are approved runtime dependencies**, pending the Phase 1 week-one UI check (spec §11). If that check fails, this entry and the two above get revisited before any more UI is built on them.
- **2026-10-12 · Decimal columns come back as strings on Postgres.** Verified on Postgres 18 with `pg` 8.23. node-postgres returns `decimal`/`numeric` as strings with the scale kept (`'1750.50'`), through Lucid models and the query builder alike. `count(*)` (bigint) and `sum()` are strings too. SQLite (better-sqlite3) returns numbers for all of these. Lucid's paginator `total` and integer columns are numbers on both. Lucid's schema generator follows the driver: it types decimals as `string` when generating from Postgres and `number` from SQLite (`NUMERIC` affinity), so `database/schema.ts` depends on which database generated it. `apps/demo/tests/functional/database/numeric_columns.spec.ts` pins all of this, and CI runs it on both databases. Consequences:
  - Number fields, number columns and currency formatting must accept decimal strings and keep them exact (no `parseFloat` on money).
  - `column.number()` / `field.number()` are currently typed for `number` attributes, so a schema generated from Postgres (`price: string`) would fail `tsc`. Decide how decimal attributes are typed (accept `string`, or a separate `decimal` type) when building number fields (FR-07).
  - Aggregates such as `hasMany` counts must be normalised to numbers before they reach the UI.
  - The demo keeps generating `database/schema.ts` from SQLite; the `pg` connection has schema generation off so the file doesn't flip types. On Postgres the demo's decimal attributes are therefore declared `number` but hold strings at runtime; tests read them through `unknown`.
- **2026-10-12 · CI runs on GitHub Actions with Node 24 (from `.nvmrc`).** Lint and typecheck once; tests (core and demo) on Postgres 18 and SQLite, plus the demo seeder. MySQL joins the matrix when Phase 1 needs it.
- **2026-10-12 · `azu()` Vite plugin lives in core at `@mezielabs/azu/vite` (FR-01).** It adds the admin entry through `environments.client.build.rolldownOptions.input`, which Vite concatenates. It doesn't use `build.*.input`, because `@adonisjs/vite` would then drop its own `entryPoints`. Its `resolve.dedupe` defaults to the peer dependencies of the installed front-end package, read from disk, so core never hard-codes React. Core imports only Vite's types, so `vite` is an optional peer, not a runtime dependency.
- **2026-10-12 · `node ace add @mezielabs/azu` installs the front-end package rather than core depending on it.** The configure hook installs `@mezielabs/azu-react`, following Lucid's `--install`/`--no-install` convention. A Vue package can later be a choice at install time.
- **2026-10-12 · Admin pages render through a per-request Inertia instance with Azu's own root view.** `AdminInertiaMiddleware` replaces `ctx.inertia` on admin routes with one rendering `azu::admin`, as proven in the spike. The app's `config/inertia.ts` and layout stay untouched, and the app's shared props don't reach admin pages. Known coupling: `azu::admin` calls `@viteReactRefresh()`, so the root view moves to the front-end package or becomes configurable when Vue arrives.
- **2026-10-12 · FR-01 ships without `accessAdmin` and `start/admin.ts`.** A fresh starter has no Bouncer, so the ability lands with the access gate (FR-02), and `start/admin.ts` with resource registration (FR-03). Until FR-02, `/admin` is open to anyone who can reach the app.
- **2026-10-12 · Generated files end with a newline; codemod output isn't reformatted.** AdonisJS stub rendering trims output, so the configure hook appends the final newline Prettier expects. The `updateRcFile` and `registerVitePlugin` codemods (used by every AdonisJS package) leave out trailing commas, which the app's lint flags until `pnpm format`. That's upstream behaviour, so the installer doesn't run Prettier on the app.
- **2026-10-12 · Decimal columns get their own `decimal` type and stay strings end to end.** `column.decimal()` and `field.decimal()` take attributes typed `string` (decimal columns as generated from Postgres); `number()` stays for `number` attributes. Values are never converted through `Number`; formatting uses `Intl.NumberFormat`, which formats numeric strings exactly. In Node 24, `format('12345678901234567.89')` keeps the cents, while `format(Number(...))` gives `.00`. VineJS has no string-decimal rule, so validators for decimal fields use `vine.string().regex(...)`; Azu adds no rule of its own (non-negotiable 1). Why: Postgres and MySQL return decimals as strings, and money must stay exact.
- **2026-10-12 · The demo's `database/schema.ts` is generated from Postgres.** It supersedes the SQLite point in the "decimal columns come back as strings" entry above. Schema generation is on for the `pg` connection only, so decimals are typed `string`. On SQLite they still arrive as numbers at runtime, which the numeric tests pin. CI's Postgres leg fails if the committed file differs from what Postgres generates.
- **2026-10-12 · Week-one UI check approved (`docs/ui-check.md`).** React Aria Components and Tiptap 3 are confirmed as runtime dependencies of `@mezielabs/azu-react`, closing the "pending the week-one check" condition above. They're added when the first component that uses them lands.
- **2026-10-12 · No column resizing in v1.** It amends the React Aria table entry above. With a `ColumnResizer` in each header, keyboard focus lands on the resize handles and Enter can't sort. Resizing comes later through React Aria's header-menu pattern (Sort ascending, Sort descending, Resize), after its own keyboard check.
- **2026-10-12 · Optional front-end features go through `azu()`.** A lazy `import()` of an optional peer fails Rolldown's build when the peer isn't installed. So a front-end package lists optional features in an `azu` field in its `package.json`: lazy subpath, fallback subpath, required peers, and dependencies to pre-bundle. `azu()` aliases a feature to its fallback when any required peer is missing, and adds the package's dependencies and installed feature peers to `optimizeDeps.include`, so dev never re-optimizes and reloads on first use. The field is internal and undocumented for now.
- **2026-10-12 · Azu ships its own toast region.** It uses an `aria-live` region rather than React Aria's `UNSTABLE_Toast`, which isn't stable in 1.22.
- **2026-10-12 · Admin bundle budget, checked in CI.** ≤ 120 kB gz of initial admin JS, and ≤ 160 kB gz per page's lazy chunk (spec §2). Why: React Aria pages measured about 141 kB gz in the UI check, so the budget leaves room without letting pages grow unnoticed.
- **2026-10-12 · The access gate fails closed (FR-02).** `AdminAccessMiddleware` runs on every admin route. Guests are sent to `loginUrl` (a 409 location response on Inertia visits), and signed-in users must pass the app's `accessAdmin` Bouncer ability or get a 403 with `azu/errors/forbidden`. With no auth, no Bouncer, or no `accessAdmin` ability, everyone is denied, and the reason goes to the log, not the page. It reads `ctx.auth` and `ctx.bouncer` structurally, because `ctx.bouncer` is typed by the app's own generated middleware and Azu doesn't know the app's guard names. This supersedes "until FR-02, `/admin` is open" in the FR-01 entry above.
- **2026-10-12 · The installer adds `accessAdmin` but doesn't install Bouncer.** `node ace configure @mezielabs/azu` appends an ability that returns `false` to `app/abilities/main.ts`, adding the Bouncer import if needed, and leaves an existing `accessAdmin` alone. Without Bouncer it warns with the two commands to run and changes nothing, following the AdonisJS presets, which don't install their dependencies either (the auth preset assumes session). `@adonisjs/auth` and `@adonisjs/bouncer` are peers of core, imported for types only.
- **2026-10-12 · The resource schema is plain JSON, defined in core (FR-03).** `defineResource` returns a `Resource` whose `toSchema()` gives a `ResourceSchema` of column, field, filter and action schemas. All JSON, with `null` for absent values rather than `undefined`, so it survives serialisation unchanged and a Vue package can share it. Handlers, hooks, validators and the policy never leave the server.
- **2026-10-12 · Builders keep the README's imported-builder API, checked at `defineResource`.** As proven in the spike, each builder captures its name as a literal type, and `defineResource` checks the arrays against unions computed from the model, with `NoInfer` on the model. Kind-specific methods use generic `this` parameters, so they only compile on the right kind and chaining keeps the precise type. `filter.custom` and `action.*.handle` are generic over the model or record, so TypeScript infers their query and records from the resource. Non-custom filters default their model parameter to `never` rather than `any`, which would otherwise win that inference.
- **2026-10-12 · Explicit registration goes through the `azu` service.** `@mezielabs/azu/services/main` exports the container-bound `Azu` service, following the AdonisJS service pattern, and `start/admin.ts` calls `azu.register(...)`. Autoload and explicit registration share one registry. Registering the same resource twice is a no-op, and two resources with the same URL name are an error at boot. Resources carry a `Symbol.for` brand, so discovery recognises them even across two copies of the package.
- **2026-10-12 · Navigation is built per request from each policy's `viewList`.** A resource the user can't list never appears, and the resource route checks `viewList` on the server too: 403 if denied, 404 if unknown. A missing `viewList` method, a missing policy, or no Bouncer hides the resource (missing means denied). Grouping and alphabetical order are in now; explicit ordering is FR-16.
- **2026-10-12 · Default columns and fields wait for the generator (FR-04).** Spec §4 says omitting `columns` or `fields` falls back to what the generator would produce. TypeScript types are erased at runtime, so that needs the database's column metadata, which the generator reads. Until then, omitted lists are empty.
- **2026-10-12 · The demo keeps `.adonisjs/` in git.** Re-checked against the official AdonisJS 7 starter kits (latest commit 27 Sep 2026): none of the five ignores `.adonisjs/`, and all of them track it (`inertia-react` tracks 10 files). We follow the starter. The cost is churn: codegen can rewrite these files with no type change, for example by reordering `pages.d.ts` entries, and `pnpm typecheck` runs codegen first. Revisit if that churn starts showing up in reviews.
- **2026-10-13 · List state lives in the URL, parsed and built by shared plain-TS modules (FR-05).** The parameters are `search`, `sort`, `direction` (`asc`/`desc`), `page` and `perPage` (10/25/50/100), with defaults left out. Invalid values fall back to defaults rather than erroring, sorting only accepts sortable columns, and a page past the end redirects to the last page (with `withQs(false)`, since apps can forward query strings on redirects by default). `@mezielabs/azu/shared` holds this and the cell formatting, with no AdonisJS or UI imports, so the server and every front end use the same rules (non-negotiable 11).
- **2026-10-13 · The shared `azu` page props are lazy.** They're a callback, so Inertia partial reloads that ask only for `list` (paging, sorting, searching) skip rebuilding the navigation and its per-resource `viewList` checks.
- **2026-10-13 · `belongsTo` columns are preloaded with `preloadOnce`.** Lucid keys preloads by relation, so a second `preload()` would silently replace the resource's own (and its callback). `preloadOnce` keeps it. The N+1 test checks both that the query count doesn't grow with rows and that every related title is present: Lucid never lazy-loads, so a missing preload shows up as empty cells, not extra queries.
- **2026-10-13 · Decimal cells keep their scale.** `formatDecimal('1750.50')` shows `1,750.50`: the fraction digits come from the string, and currency uses the currency's precision. SQLite returns decimals as numbers, so there the scale is already lost (`1750.5`).
- **2026-10-13 · Search needs trigram indexes on Postgres.** At 100,000 products, `ILIKE '%term%'` on name and SKU took 598 ms p95 with a sequential scan. `pg_trgm` GIN indexes brought it to 36 ms, and the demo adds them in a Postgres-only migration. Indexes stay the app's job, so the README recommends them. A term matching every row still costs 162 ms p95: under target, but the closest to it. A minimum search length or an estimated count are the levers if that matters.
- **2026-10-13 · Clicking a row selects it, for now.** That's React Aria's default "toggle" selection. When FR-06 adds row links, rows get an action (open the record) and selection stays on the checkboxes. The selection clears whenever the rows change.
- **2026-10-13 · List search matches `%` and `_` literally, with `ESCAPE '!'`.** Search terms escape `%`, `_` and `!`, and the SQL is `col ILIKE ? ESCAPE '!'` on Postgres and `col LIKE ? ESCAPE '!'` on SQLite and MySQL, which are case-insensitive for ASCII and with MySQL's default collations. `!` rather than backslash: backslashes need escaping inside MySQL string literals, and SQLite has no default escape character. On 100,000 products, Postgres still uses the trigram indexes with `ESCAPE`, for literal and parameterized patterns alike.
- **2026-10-13 · CI runs MySQL 8.4 too.** The demo has a `mysql` connection (mysql2, schema generation off; Postgres stays the source of `database/schema.ts`). Migrations, the seeder and every test pass on it. MySQL returns decimals and `sum()` as strings with the scale kept, like Postgres, but `count(*)` as a number, like SQLite. The numeric tests pin each database's values.
- **2026-10-13 · Forms submit to their own URL, and a failed save is a 422 render, not a redirect (FR-06, FR-10).** `POST …/create` and `PUT …/:id/edit`. A validation failure renders the same form page with status 422 and an `errors` prop keyed by VineJS path. Inertia v3 renders an Inertia response with an error status as a page, and the form submits with `preserveState`, so the user's input stays. Why not AdonisJS's usual flash-and-redirect-back: it needs the session, and the page URL comes from the request URL, so the form has to own its URL either way. Posting to the list URL would leave the address bar there after a 422.
- **2026-10-13 · Saves write only what the user was shown and the validator returned.** The payload is cut to fields the form showed (`visibleOn`, field `ability`), minus `readOnly`. Then the validator's output is cut to the same names before `merge`, so a validator transform that adds keys can't write undeclared attributes. Update falls back to the create validator. A resource with no validator for the operation throws a developer error rather than writing unvalidated input. `beforeSave`, the save and `afterSave` run in `Model.transaction()`.
- **2026-10-13 · A field's `ability` gates it on forms and detail pages now, not only in FR-11.** Leaving it out until FR-11 would have let anyone who can `update` write a gated field. It's checked with the record on edit and detail.
- **2026-10-13 · A missing policy method is denied without asking Bouncer.** Bouncer throws for a missing method, so Azu checks the policy's prototype first. That's quiet, because resources without `create` or `update` are normal (orders here). A policy that throws is still logged.
- **2026-10-13 · Datetimes are submitted as wall-clock time in the app's timezone.** `YYYY-MM-DD HH:mm:ss` is what `vine.date()` accepts by default, and the server parses it in its own timezone, which is the app's. So apps' validators work without a custom format. The cost: the repeated hour at a DST change (01:00–02:00 on the last Sunday of October in London) is ambiguous, and the server picks the first. Dates are `YYYY-MM-DD`. Form state keeps exact instants; conversion happens on submit.
- **2026-10-13 · `@internationalized/date` is a runtime dependency of `@mezielabs/azu-react`** (approved by Chimezie). React Aria's date pickers take its `CalendarDate` and `ZonedDateTime`, and `react-aria-components` doesn't re-export them. It was already installed as a dependency of React Aria.
- **2026-10-13 · Success toasts come from the form, not a server flash.** The form shows "Coupon created" when Inertia reports the redirect's page as a success. That needs no session. The toast store lives outside React, and the region is rendered once beside the Inertia app, so the `aria-live` region exists before the toast arrives and screen readers announce it. Server-driven messages (action results, FR-12) can use the same region.
- **2026-10-13 · Rows link through React Aria's `href`.** This replaces "Clicking a row selects it, for now" above. A row the user may `view` gets an `href`, and a `RouterProvider` in `createAzuApp` sends it through Inertia. With "toggle" selection, a click or Enter opens the record, and the checkbox or Space selects. Rows say whether they link through `abilities.view`, checked per row on the server.
- **2026-10-13 · Unsaved-changes warning: a dialog for Inertia visits, the browser's prompt for unloads.** Inertia's cancelable `before` event catches links and navigation; non-GET visits (the form's own submit) pass. `beforeunload` covers reloads, closing the tab, and leaving the app. Inertia can't intercept the back button between pages of the same app, so that one leaves without asking.
- **2026-10-13 · Field kinds outside FR-06 are left out of forms, not stubbed.** `richText`, `file`, `image` and relation fields don't render, show on detail pages, or write until FR-07 and FR-08. Validator errors for attributes the form doesn't show go to a summary at the top of the form, so nothing fails silently. That's why the demo's Product edit form reports `stock` and `categoryId` until FR-08.
- **2026-10-13 · The demo gains a Coupon resource.** It exercises every FR-06 field kind (text, textarea, a 3-option select as radios, a 6-option select as a dropdown, decimal, number, boolean, date, datetime) and the default `{ record }` metadata in its update validator. Staff may view coupons but not create or update them, which drives the forbidden-path tests. Category gained validators too; Product maps metadata with `validators.meta`, as in the README.
- **2026-10-13 · An impossible id is a 404.** Postgres rejects `abc` or an out-of-range number for an integer key (`22P02`, `22003`). `findRecord` treats that as no record, and the query still goes through the resource's `query` hook.
- **2026-10-14 · The admin timezone is a setting, and datetimes are submitted as exact instants.** This replaces "Datetimes are submitted as wall-clock time in the app's timezone" above.
  - **What was off:** with the server process in UTC and admins in Africa/Lagos, a datetime entered as 14:30 Lagos was stored as 14:30 UTC, an hour late. Azu treated the process timezone as the app's, and `vine.date()` parses wall-clock strings in the process timezone. Across London's DST change on 2026-10-25, the repeated 01:30 couldn't be expressed at all.
  - **The setting:** `timezone` in `config/admin.ts` (IANA name; default: the process timezone, so existing apps behave as before). Chimezie chose it over following Luxon's `Settings.defaultZone`, which would have made luxon a peer dependency of core. Pickers, list cells and detail pages use it.
  - **The fix:** the form sends the instant React Aria resolved (`toAbsoluteString()`), so the two 01:30s differ by offset. Before validation, `toValidatorDateTime` (plain `Intl`) rewrites each datetime field as `YYYY-MM-DD HH:mm:ss` in the process timezone, which `vine.date()` accepts by default. The app's validator runs unchanged, still the only source of truth. Wall-clock strings from other clients are read in the admin timezone; a repeated time takes the first occurrence, and a skipped one moves forward.
  - **What remains:** if the server process itself runs in a DST zone, the string handed to `vine.date()` is ambiguous for the repeated hour, and dayjs picks one. Running the server in UTC, as AdonisJS's starter does, avoids it. Validators with custom `vine.date({ formats })` need to accept `YYYY-MM-DD HH:mm:ss` for datetime fields.
  - **Tests:** `apps/demo/tests/functional/admin/timezones.spec.ts` runs with `TZ=UTC` (pinned in `.env.test`). It covers Lagos, and London either side of the change, including both 01:30s, on all three databases. `packages/core/tests/datetime_input.spec.ts` covers the conversion, the gap and the overlap.
