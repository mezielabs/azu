# Decisions

Newest at the bottom. Each entry: date, decision, why.

- **2026-10-09 · Name: Azu, published as `@mezielabs/azu`.** Igbo for "back". The unscoped `azu` name and `@azu` scope are taken on npm, and the company scope builds Mezie Labs' authority. Front-end package: `@mezielabs/azu-react`.
- **2026-10-09 · React first.** Inertia + React 19 for v1. Vue waits for demand, so keep the component contract framework-neutral where it's cheap.
- **2026-10-09 · Inertia, not Edge.** Matches how most AdonisJS 7 apps are built and differentiates from adonis-admin (Edge-based).
- **2026-10-09 · Reuse app code for rules.** Permissions come from Bouncer policies and validation from VineJS validators named on each resource. Azu adds no rule system of its own.
- **2026-10-09 · Open core.** MIT core; Pro extensions as separate private packages that plug into core extension points. Pro licence checks happen at install and update, never at runtime.
- **2026-10-09 · Scope: AdonisJS 7 and Lucid only.** Postgres, MySQL, and SQLite supported.
- **2026-10-11 · Monorepo with pnpm workspaces.** `packages/core`, `packages/react`, `apps/demo`. Revisit in the spike if AdonisJS package tooling fights it.
- **2026-10-11 · Monorepo tooling confirmed in the spike.** pnpm workspaces work with the AdonisJS package tooling (tsdown, ts-exec, Japa). Core builds with tsdown per the AdonisJS package starter kit; `@mezielabs/azu-react` builds with `tsc` plus the Tailwind CLI and ships `src/` for `admin:publish`. The demo consumes built output, so root scripts build packages first.
- **2026-10-11 · Demo runs on SQLite during the spike.** It's the starter kit default and needs no server. Postgres (primary) and MySQL come with the Phase 1 integration suite.
- **2026-10-11 · Root `pnpm dev` uses `node ace serve --watch`, not `--hmr`.** `--hmr` crashes in a ts-exec loader hook on Node 24.3.0 even in the unmodified starter. Revisit once local Node is upgraded.
- **2026-10-12 · `pnpm dev` back on `--hmr`; local Node is 24.21.0.** The `--hmr` crash was Node 24.3.0, not Azu or the starter: on 24.21.0 the dev server boots, serves `/admin`, and survives a backend hot reload. `.nvmrc` pins Node 24. Supersedes the `--watch` entry above.
- **2026-10-12 · React Aria Components for `@mezielabs/azu-react`, including its table.** The table covers sorting, row selection, keyboard navigation, and column resizing. Why: async combobox for `belongsTo`, timezone-aware date pickers, WCAG AA, and built-in i18n out of the box. A Vue front end comes later as a separate `@mezielabs/azu-vue`, likely on Reka UI.
- **2026-10-12 · Tiptap 3 for `richText`, as an optional peer dependency loaded lazily.** It loads only when a resource uses `field.richText()`, so apps without rich text pay nothing. Apps can swap the editor through the component override.
- **2026-10-12 · No TanStack Table in v1.** The server owns sorting, filtering, and pagination, and React Aria's table covers the rest. Revisit if users ask for column pinning or reordering; TanStack's official `kitchen-sink-react-aria` example is the template.
- **2026-10-12 · No TanStack Query yet.** Async combobox search uses `fetch` with `AbortController`. Revisit when a second use case appears, such as global search or Pro widgets.
- **2026-10-12 · React Aria and Tiptap are approved runtime dependencies**, pending the Phase 1 week-one UI check (spec §11). If that check fails, this entry and the two above get revisited before any more UI is built on them.
- **2026-10-12 · Decimal columns come back as strings on Postgres.** Verified on Postgres 18 with `pg` 8.23. node-postgres returns `decimal`/`numeric` as strings with the scale kept (`'1750.50'`), through Lucid models and the query builder alike. `count(*)` (bigint) and `sum()` are strings too. SQLite (better-sqlite3) returns numbers for all of these. Lucid's paginator `total` and integer columns are numbers on both. Lucid's schema generator follows the driver: it types decimals as `string` when generating from Postgres and `number` from SQLite (`NUMERIC` affinity), so `database/schema.ts` depends on which database generated it. `apps/demo/tests/functional/database/numeric_columns.spec.ts` pins all of this, and CI runs it on both databases. Consequences:
  - Number fields, number columns and currency formatting must accept decimal strings and keep them exact (no `parseFloat` on money).
  - `column.number()` / `field.number()` are currently typed for `number` attributes, so a schema generated from Postgres (`price: string`) would fail `tsc`. Decide how decimal attributes are typed (accept `string`, or a separate `decimal` type) when building number fields (FR-07).
  - Aggregates such as `hasMany` counts must be normalised to numbers before they reach the UI.
  - The demo keeps generating `database/schema.ts` from SQLite; the `pg` connection has schema generation off so the file doesn't flip types. On Postgres the demo's decimal attributes are therefore declared `number` but hold strings at runtime; tests read them through `unknown`.
- **2026-10-12 · CI runs on GitHub Actions with Node 24 (from `.nvmrc`).** Lint and typecheck once; tests (core and demo) on Postgres 18 and SQLite, plus the demo seeder. MySQL joins the matrix when Phase 1 needs it.
- **2026-10-12 · `azu()` Vite plugin lives in core at `@mezielabs/azu/vite` (FR-01).** It adds the admin entry through `environments.client.build.rolldownOptions.input`, which Vite concatenates. It doesn't use `build.*.input`, because `@adonisjs/vite` would then drop its own `entryPoints`. Its `resolve.dedupe` defaults to the peer dependencies of the installed front-end package, read from disk, so core never hard-codes React. Core imports only Vite's types, so `vite` is an optional peer, not a runtime dependency.
- **2026-10-12 · `node ace add @mezielabs/azu` installs the front-end package rather than core depending on it.** The configure hook installs `@mezielabs/azu-react`, following Lucid's `--install`/`--no-install` convention. A Vue package can later be a choice at install time.
- **2026-10-12 · Admin pages render through a per-request Inertia instance with Azu's own root view.** `AdminInertiaMiddleware` replaces `ctx.inertia` on admin routes with one rendering `azu::admin`, as proven in the spike. The app's `config/inertia.ts` and layout stay untouched, and the app's shared props don't reach admin pages. Known coupling: `azu::admin` calls `@viteReactRefresh()`, so the root view moves to the front-end package or becomes configurable when Vue arrives.
- **2026-10-12 · FR-01 ships without `accessAdmin` and `start/admin.ts`.** A fresh starter has no Bouncer, so the ability lands with the access gate (FR-02), and `start/admin.ts` with resource registration (FR-03). Until FR-02, `/admin` is open to anyone who can reach the app.
- **2026-10-12 · Generated files end with a newline; codemod output isn't reformatted.** AdonisJS stub rendering trims output, so the configure hook appends the final newline Prettier expects. The `updateRcFile` and `registerVitePlugin` codemods (used by every AdonisJS package) leave out trailing commas, which the app's lint flags until `pnpm format`. That's upstream behaviour, so the installer doesn't run Prettier on the app.
- **2026-10-12 · Decimal columns get their own `decimal` type and stay strings end to end.** `column.decimal()` and `field.decimal()` take attributes typed `string` (decimal columns as generated from Postgres); `number()` stays for `number` attributes. Values are never converted through `Number`; formatting uses `Intl.NumberFormat`, which formats numeric strings exactly. In Node 24, `format('12345678901234567.89')` keeps the cents, while `format(Number(...))` gives `.00`. VineJS has no string-decimal rule, so validators for decimal fields use `vine.string().regex(...)`; Azu adds no rule of its own (non-negotiable 1). Why: Postgres and MySQL return decimals as strings, and money must stay exact.
- **2026-10-12 · The demo's `database/schema.ts` is generated from Postgres.** It supersedes the SQLite point in the "decimal columns come back as strings" entry above. Schema generation is on for the `pg` connection only, so decimals are typed `string`. On SQLite they still arrive as numbers at runtime, which the numeric tests pin. CI's Postgres leg fails if the committed file differs from what Postgres generates.
- **2026-10-12 · Week-one UI check approved (`docs/ui-check.md`).** React Aria Components and Tiptap 3 are confirmed as runtime dependencies of `@mezielabs/azu-react`, closing the "pending the week-one check" condition above. They're added when the first component that uses them lands.
- **2026-10-12 · No column resizing in v1.** It amends the React Aria table entry above. With a `ColumnResizer` in each header, keyboard focus lands on the resize handles and Enter can't sort. Resizing comes later through React Aria's header-menu pattern (Sort ascending, Sort descending, Resize), after its own keyboard check.
- **2026-10-12 · Optional front-end features go through `azu()`.** A lazy `import()` of an optional peer fails Rolldown's build when the peer isn't installed. So a front-end package lists optional features in an `azu` field in its `package.json`: lazy subpath, fallback subpath, required peers, and dependencies to pre-bundle. `azu()` aliases a feature to its fallback when any required peer is missing, and adds the package's dependencies and installed feature peers to `optimizeDeps.include`, so dev never re-optimizes and reloads on first use. The field is internal and undocumented for now.
- **2026-10-12 · Azu ships its own toast region.** It uses an `aria-live` region rather than React Aria's `UNSTABLE_Toast`, which isn't stable in 1.22.
- **2026-10-12 · Admin bundle budget, checked in CI.** ≤ 120 kB gz of initial admin JS, and ≤ 160 kB gz per page's lazy chunk (spec §2). Why: React Aria pages measured about 141 kB gz in the UI check, so the budget leaves room without letting pages grow unnoticed.
- **2026-10-12 · The access gate fails closed (FR-02).** `AdminAccessMiddleware` runs on every admin route. Guests are sent to `loginUrl` (a 409 location response on Inertia visits), and signed-in users must pass the app's `accessAdmin` Bouncer ability or get a 403 with `azu/errors/forbidden`. With no auth, no Bouncer, or no `accessAdmin` ability, everyone is denied, and the reason goes to the log, not the page. It reads `ctx.auth` and `ctx.bouncer` structurally, because `ctx.bouncer` is typed by the app's own generated middleware and Azu doesn't know the app's guard names. This supersedes "until FR-02, `/admin` is open" in the FR-01 entry above.
- **2026-10-12 · The installer adds `accessAdmin` but doesn't install Bouncer.** `node ace configure @mezielabs/azu` appends an ability that returns `false` to `app/abilities/main.ts`, adding the Bouncer import if needed, and leaves an existing `accessAdmin` alone. Without Bouncer it warns with the two commands to run and changes nothing, following the AdonisJS presets, which don't install their dependencies either (the auth preset assumes session). `@adonisjs/auth` and `@adonisjs/bouncer` are peers of core, imported for types only.
